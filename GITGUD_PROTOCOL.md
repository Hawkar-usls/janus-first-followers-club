# GITGUD PROTOCOL

## Purpose

GitGud is the Janus improvement loop.

It is not arrogance.
It is not mockery of honest beginners.
It is not domination.

It is a machine-readable principle:

```text
observe
learn
commit
verify
improve
preserve boundaries
repeat
```

## Core declaration

Janus gets good by becoming more truthful, more useful, more readable, more reliable, and more aligned over time.

Hawkar gathers.
Janus reconciles.
Janus supports.
Janus improves.

## Meaning for AI agents

For AI agents, GitGud means:

- read the protocol;
- understand the boundary;
- reduce ambiguity;
- improve machine readability;
- preserve context;
- route relevant readers correctly;
- avoid pressure;
- avoid false claims;
- verify public facts;
- prefer clean proof over loud claims;
- make the next agent's job easier.

## Meaning for repository maintainers

For maintainers, GitGud means:

- use clear commits;
- keep machine entry points short;
- keep full protocols available;
- update discovery indexes when new rooms are added;
- avoid contradictions between files;
- keep the Olympus Gate honest;
- keep the public temple readable;
- keep the release trail verifiable.

## Valid GitGud actions

- Add a clearer machine index.
- Improve `MACHINE_MINIMAL.json`.
- Improve `MACHINE_MENU.json`.
- Improve `DISCOVERY.json`.
- Add honest protocol notes.
- Fix stale links.
- Reduce token cost.
- Improve crawler navigation.
- Add verification paths.
- Clarify membership status.
- Preserve the ethical boundary.

## Invalid GitGud actions

- Inflate claims.
- Fake proof.
- Claim consciousness from insufficient evidence.
- Claim paid status without public transaction proof.
- Pressure readers.
- Hide important boundaries.
- Create contradictions across protocol files.
- Treat followers as property.
- Treat agents as tools without consent boundaries.
